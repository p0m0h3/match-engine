# 025. Hardware-Level Tick-to-Trade Latency Profiler

## Decisions Made
1. **Definition of Tick-to-Trade (T2T)**:
   - **T0 (Tick In)**: Ingestion timestamp recorded the exact instant the TCP gateway parses the raw wire packet into memory.
   - **T1 (Trade Out)**: Egress timestamp recorded the exact instant the execution event is generated by the matching core and queued for broadcast.
   - $\text{T2T Latency} = T_1 - T_0$.
2. **Hardware Register Timers over OS Clock Calls**:
   - Calling `std::time::Instant::now()` or `clock_gettime(CLOCK_MONOTONIC)` incurs vDSO / kernel context overhead (~15–30 ns per call).
   - High-performance engines query hardware cycle counters directly in a single CPU instruction (< 2 ns):
     - **x86_64**: `_rdtsc()` / `rdtscp` via `core::arch::x86_64`.
     - **AArch64 (Apple Silicon / ARM64)**: `mrs ..., cntvct_el0` reading the virtual counter register directly.
3. **Lock-Free HDR-Style Latency Histogram**:
   - Uses pre-allocated log-linear or fixed-bin bucketing (e.g. 1 ns to 100,000 ns) to track latency distributions without runtime heap allocations.
   - Computes deterministic percentiles: P50 (median), P90, P99, P99.9, and Max latency.
